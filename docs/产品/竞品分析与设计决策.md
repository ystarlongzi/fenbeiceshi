# 四个分贝产品的竞品分析与设计决策

研究日期：2026-10-17。对象为用户指定的四个中文页面。结论来自实际浏览器渲染、交互、公开 DOM 与元数据，不代表流量、准确度或隐私实现经过审计。

## 1. 研究范围与结论

检查桌面 1280×720 与手机模拟视口 390×844，阅读首页全部可见模块，检查导航、内容体系、语言关系和结构化数据，并执行仪表样式切换、全屏进入/退出、Esc 退出和第三站演示模式。另阅读第三站校准指南。

没有向竞品授予真实麦克风权限，没有上传音频、安装 App、生成真实测量报告、运行性能实验或取得搜索量数据。手机模拟视口验证布局，不等于真实 iPhone/Android 音频兼容性验证。隐私、准确度、频谱与计权等声明只记作竞品声明。

| 产品                                                                | 核心任务                 | 最值得借鉴                                  | 本站应解决的缺口                                 |
| ------------------------------------------------------------------- | ------------------------ | ------------------------------------------- | ------------------------------------------------ |
| [Free Online Decibel Meter](https://freeonlinedecibelmeter.com/zh/) | 直接测量，按偏好切换显示 | 多仪表共用会话；全屏隐藏无关内容            | 未测量的零值和环境判断；样式数量与文案不同步     |
| [Real-time Sound Meter](https://realtimesoundmeter.com/zh/)         | 数字、频率、趋势并置     | `bottom-scale-section` 将数值与连续位置关联 | 手机操作靠后；尚未取数就展示安全结论；中文不完整 |
| [Online Decibel Meter](https://onlinedecibelmeter.org/zh-CN)        | 即时估算、演示与设备校准 | 明确标注估算、非 dBA；颜色结合文字与图标    | 首屏留白压低开始按钮；默认通用映射不适合本站口径 |
| [ToolKK 噪迹分贝仪](https://www.toolkk.com/apps/noise-trace)        | 推广移动 App 并引导下载  | 产品截图叙事、深绿层次、场景卡片内部组织    | 首页不是可直接使用的 Web 工具；不能照搬宣传首屏  |

共同机会：把可立即操作的工具、清楚的测量口径和有方法的内容组合起来，减少“只有漂亮读数”与“只有长篇说明”之间的断裂。

## 2. 第一站：样式是观察方式，全屏是任务模式

### 已观察的结构与行为

- 顶部提供语言、主题和样式入口；主体为仪表、状态、开始/全屏/切换/报告操作，再到统计、样式列表和长篇知识。
- 实际展示经典指针、数码 LED、波形 FFT、极简、HUD、Pulse Ring、Bar Graph、Pure Text，共 8 个选项；页面说明及 WebApplication 数据仍描述 5 种。
- 已切换指针和 LED；选择项有缩略图、名称、用途、选中边框与状态。选择后主仪表切换；未验证运行期间是否确实无数据损失。
- 全屏隐藏导航、知识、样式列表和统计区，保留仪表、状态及操作。退出按钮和 Esc 均能返回普通页面。
- 经典仪表在桌面首屏视觉比重较大，开始按钮落到首屏下方；LED 状态在手机上更紧凑。手机 390×844 中，开始按钮文档位置约 465px。

### 判断

指针帮助理解变化方向，数显帮助远处读取，简洁条形便于持续观察。它们应共享同一数据、计时与会话；不应变成 8 套各自拥有计数器和权限逻辑的组件。

全屏真正的价值在于持续观察，不只是放大一个数字。本站应保留时间、模式、结束操作与必要统计，避免进入全屏后失去判断依据。开始前显示 `0.0 dB` 并称环境安静，会把缺失数据误当作测量结果，本站改为 `— —` 和“等待开始”。

### 内容与增长

有原理、对照、步骤、场景、FAQ 和信任页面，并提供多语言 canonical/alternate。页面具备完整解释路径，但首页内容较长、同义表达较多；FAQ 与可见样式数量维护不一致。中文首页的 WebApplication 名称、说明和 URL 仍为英文根页信息，应检查本地化内容的一致性。本站以真实功能注册生成对应说明，不复制其文案或全部样式。

## 3. 第二站：连续刻度应连接数字与位置

### 指定模块的拆解

`bottom-scale-section` 位于工具工作区底部，内部顺序是：数值刻度 → 水平轨道与填充 → 分段文字。桌面实际宽约 986px，顶部留白 20px。

轨道采用绿、蓝、橙、红连续渐变，标签带各自颜色，填充跟随当前值变化。初始零值时彩色填充不可见，主要靠标签提示范围。这个结构让刻度成为仪表的共同解释层，优于在远处另放一张毫无联系的表格。

实际刻度标签为 0、40、70、85、100、120，横向起点约 0、180、370、558、747、942px；数字间隔不等，标签却接近等距。若当作线性 dB 轴，空间位置容易误导。本站按 `(value - min) / (max - min)` 计算位置，分段标签作为图例时另行排布。

### 整体设计与流程

- 左侧读数、统计和说明，右侧频率与 30 秒历史；工作区下方接使用步骤、参考表、原理、限制、报告、场景、FAQ、文章与来源。
- 主数字、最小/平均/最大三项快速摘要，以及读数—趋势并列关系，适合桌面观察。
- 默认停止且未取数时，仍显示零值及“安全、长时间暴露无风险”一类结论，状态与证据不匹配。
- 手机布局先显示较长提示再显示开始按钮，实测按钮顶部约 801px、高约 64px，在 844px 高视口中不完整可见。
- 中文正文中夹有英文导航、按钮、图表和页脚；部分中文内容入口直接进入英文路径。

### 内容与增长

将测量、对照表、听觉测试、扬声器测试和博客组织成工具网络，回访和交叉使用的理由比单一页面充分。首页示例报告有明确示例标注，值得借鉴；同时健康解释占据大量篇幅，准确性范围和安全结论需要独立证据，不能因为写了机构名称就接受其全部阈值或误差声明。

本站第一批聚焦声音观察；后续只增加具有独立输入和输出的工具。保留相关内容入口，不在首页引入一组暂时无法验证的健康工具。

## 4. 第三站：色彩编码需要对应口径与状态

### 已观察的结构与行为

- 初始圆环与数字用中性灰、未取数用破折号；当前值旁直接标注“估算 dB SPL”，并明确不是 dBA 或认证测量。
- 演示可以不授权麦克风运行，带演示标记；停止后历史仍为 0 条，未将模拟数据混入测量记录。
- 圆环和数值采用一致强调色；统计以图标区分最大、最小、平均，波形使用独立深色表面。
- 运行状态仍保留“点击开始”的静态帮助，说明状态文案需要随流程维护。
- 桌面大标题和宽大圆环带来较多留白；手机开始按钮顶部约 877px，位于 844px 视口下方。

### 校准与内容

[校准指南](https://onlinedecibelmeter.org/zh-CN/calibration) 明确单点偏移无法纠正频响、自动增益、压缩与削波，也说明设备、浏览器或处理设置变化后的失效风险。这种“数据旁有口径、教程内有条件”的结构值得保留。

导航按教程、对照、保护、睡眠、法规、降噪与校准分工，页面本地化和栏目对应比较完整。当前渲染 DOM 可见 WebSite、WebPage 数据及 6 个 alternate（含 x-default）；这些信号不能证明其收录或排名效果。

本站采用更严格的产品口径：默认仅展示 dBFS；建立参考后才显示估算声级。颜色在未校准时表示数字输入的幅度变化和接近满幅风险，不赋予环境安全含义。色彩必须同时有文字、单位与状态，避免靠红绿判断一切。

## 5. ToolKK：卡片内的层级来自信息角色

这是 App 产品介绍页，浏览器“开始测量”实际跳到下载区域。本次只分析介绍、截图、场景和下载入口，不据此评价 App 的测量能力。

### 指定网格

目标 `mt-12 grid gap-4 sm:grid-cols-2 lg:grid-cols-4` 为四个场景：居家、办公、学习、户外。桌面 4 列，卡间 16px；手机一列，实际单列宽约 350px。每张内边距 24px、最小高度约 210px，深绿渐变与低对比边界建立对象表面。

内部有四个明确角色：

1. 左上图标：快速识别场景。
2. 靠下的较强标题：明确对象名称。
3. 标题下的次级说明：解释何时有用；换行自然增长。
4. 右上的低对比大编号：提供背景节奏，不争夺阅读权重。

上下间距不是等分。图标区与文字区拉开距离，标题与说明保持靠近；边界、渐变、色相与留白协作产生内部层次，并非再嵌套一张卡片。编号不是必要信息，不能依赖它表达顺序或选择状态。

### 整站叙事

深色基底、绿色强调、叠放手机截图、功能块、真实截图、场景、下载，围绕 App 下载形成完整叙事。首屏以一个主操作和一个查看界面的辅助入口区分路径，图片与文案相互印证。

本站借鉴场景对象的内部排布、工作区的深绿质感和真实产品展示。Web 工具首页需要直接操作，不能照搬“大宣传标题 + 手机海报 + 下载”作为首屏。卡片只用于确实独立的场景、样式选项和指标；文章与步骤继续采用开放排版。

本次渲染 DOM 未发现 JSON-LD，不能据此断言其所有页面均无结构化数据。已观察到独立 canonical 与中、繁中、英、日及默认语言关系。未检查下载后的 App、小程序或付费能力。

## 7. 首次实现的范围与验收

先做中英首页及第一批帮助、测量状态机、三种仪表、连续刻度、趋势、全屏、输入选择、参考校准、本机摘要记录和导出。P1 场景独立页面、独立计算器、PDF 报告及后台长时间监测不纳入首次实现。

首页的角色分工：标题与简短说明识别任务；仪表和开始按钮承载主任务；输入、校准和有效时长支持判断；趋势提供时间背景；内容入口承担解释。层级通过对齐、留白、文字与表面共同建立。

验收要求：等待不显示假读数；演示不污染记录；取消权限等待后迟到的音轨必须释放；切样式和全屏不中断会话；设备变化不能沿用无效校准；结束释放音轨；本机存储失败能恢复并告知；中英与手机首屏均能找到开始操作；未知 URL 为 404；正文与来源存在于静态 HTML。

所有参考设计仅用于提炼结构与交互，不复制竞品文案、品牌、图片、样式代码或测量准确性声明。图标继续复用项目固定来源的 Lucide 资产。
