# fenbeiceshi.com 整站结构与内容 SEO 规划

版本：0.2；更新：2026-10-22。定位为竞品分析前的执行基线，后续依据竞品、真实查询和使用数据修订。

本文为整站规划，不代表所有候选功能均已完成或上线。2026-10-17 已完成本地首版：实际页面注册见 `src/lib/routing/pages.ts`，范围见 [首版实现说明](./首版实现说明.md)，证据见 [首版验证记录](../验证/首版验证记录.md)。候选关键词、P1/P2 页面与分析事件继续按规划逐批验证。

## 1. 产品定位与增长路径

面向普通用户，提供无需安装、适配手机的浏览器声音观察工具。先帮助用户完成一次有效操作，再解释读数、指导条件一致的比较，形成保存与回访的理由。

工程营销的核心资产是可反复使用的工具，以及能把问题转化为实际操作的内容。内容不只承担曝光：每个主题都应连接到合适的测量、比较、计算或排查步骤。首阶段以工具使用和回访为转化目标，暂不假定付费方案或强制注册。

增长路径：

1. 搜索“在线分贝测试” → 首页立即操作 → 理解口径 → 保存本机记录。
2. 搜索“手机测分贝准吗” → 了解适用条件 → 选择通用估算或可选参考校准 → 回到工具。
3. 搜索“房间噪音怎么测” → 按场景方法操作 → 比较同条件记录 → 后续复测。
4. 搜索“两个噪声源如何叠加” → 使用独立计算器 → 理解假设 → 收藏或引用方法。

市场选择：中文优先，兼顾百度、必应与 Google；同时规划英文工具和基础内容。简体中文位于根目录，繁体中文位于 `/zh-tw/`，英文位于 `/en/`。当前已实现页面具备三语内容；后续选题分别确认标题、查询意图、例子与语言可用性，不自动发布规划中的页面。

## 2. 能力边界必须进入页面结构

当前口径以 [噪音估算规格](../../design/noise-estimate-v1/design-spec.json) 与 [方法说明](./噪音估算口径.md) 为准，覆盖 V2/V3 的默认相对模式决定：

- 默认：显示明确标注未校准的通用估算噪音分贝。generic-rms-v1 使用 RMS dBFS +100，参数公开且记录版本；它是未经跨设备声学精度验证的产品假设，不宣称为通用 SPL 换算或量化准确度。
- 参考校准：可选操作，有效参考偏移替换通用偏移；仪表、色带、趋势、统计、记录和导出共用同一口径，保留参考来源、设备、输入设置和校准信息。原始信号在麦克风旁辅助展示。
- 更换输入设备、增益或相关处理设置后，应重新确认校准；单点偏移不代表完成全频段、全量程验证。
- 未实现并验证频率计权前，不使用 `dBA` 标签；未实现相应算法前，不把简单平均数称为 `LAeq`，不把采样窗口最高值称为专业峰值指标。
- 不把页面结果包装成法定检测报告、职业暴露评估或医学结论。健康、法规内容另设来源和复核门槛。
- 用户点击开始后才请求麦克风；音频在本机处理，不上传。同步录音默认关闭，开启后可在保存报告时将同次原始 PCM 留在当前浏览器的 IndexedDB，支持历史下载和随记录删除；当前限制见 [同步录音说明](./同步录音说明.md)。

这不是页脚才出现的说明。首页读数旁、校准流程、结果页和相关内容的操作入口都必须使用一致口径。首页标题可以覆盖“分贝测试”需求，正文必须立即说明当前模式。

## 3. 信息架构与导航

当前一级导航按用户任务组织：**开始测量、分贝对照表、声音知识、使用指南、本机记录、常见问题**；其中使用指南与常见问题在 761–1140px 紧凑桌面布局收起。手机页头保留品牌与右上角菜单按钮，点击后打开右侧抽屉，完整展示六项导航与主题／语言切换；支持关闭按钮、遮罩、Esc 关闭，选择链接后收起。分贝对照表承接快速查找声音量级的任务，独立于连续阅读的知识目录；沿用 `/knowledge/decibel-chart/` 与英文对应路径。场景方法和工具箱在具备足够已发布页面后再开放独立导航。设备与校准放在测量上下文，关于与隐私放在页脚。本机记录是功能入口，不是 SEO 栏目。

分贝对照页按 [V6 规格](../../design/decibel-chart-v6/design-spec.json) 采用七档纵向声音组，每项声音以内容决定宽度的标签展示名称、参考范围和原始单位；比较条件和分贝详情行内链接通过原生展开在标签下方整行查看，同档同时展开一项；展开说明不重复展示来源机构和资料出处，完整引用在对应详情页查看。七档简短名称下各补充一句体感描述。各档声音列表默认折叠，点击标题展开；搜索时自动展开匹配分组，清空搜索后恢复折叠。分组与声音描述均使用原生 details，完整内容保留在静态 HTML。31 项声音的展开描述内追加原生行内链接，按准确单值或完整范围进入 28 个独立主题；同值声音共页并保留各自单位和来源条件，三语共新增 84 个 URL。详情按 [V3 层级](../../design/decibel-details-v3/design-spec.json) 先给直观结论，再安排声音场景、分贝差与近似听感及能量对比、听力风险及生活化问答；手机先展示结论再放目录。正文、表格、来源及关联入口静态输出，面包屑以上层分贝对照表为父页。范围不取中点，不把所有整数机械扩成同款页面；主题清单见 [分贝详情页说明](./分贝详情页说明.md)。编组按参考范围起点进行，跨档声音保留完整数值并只出现一次；搜索名称或数值后保留匹配条目和非空分组，不再提供分段按钮、类别筛选和滑块。页首简述 40–70 分贝量级；参考说明只保留范围差异与网页估算比较两个问题。噪音与健康独立为声音对照之后的二级章节并进入目录，以一段导读和两个入口分别承接暴露时长与健康影响。健康专题按 [健康文章 V2](../../design/noise-health-v2/design-spec.json) 将职业暴露时长参考放在首章并默认展开，随后是六项简短健康影响、减少干扰、判断条件与专业帮助。职业参考支持独立手动输入、滑块及六个参考点，按 NIOSH 的 85 dBA／8 小时和 3 dBA 交换率演示，不连接仪表估算或推算个人安全倒计时；健康影响的短标题、正文与官方依据保持相邻。中英文正文、来源与单位保留静态输出，首页和知识目录直接链接健康文章。31 项声音的官方原文定位与条件以 [逐项核验记录](../验证/声音参考来源逐项核验.md) 为准；NIH 索引引用已替换为可读取的 EPA 资料和 CDC/NIOSH PDF，保留历史年份、完整范围与测距。

执行规则：

1. 不为“分贝仪、声级计、噪音检测、噪声测试”等首页近义表达分别创建同款工具页。
2. 不批量生成“40 分贝、41 分贝……”“城市 + 噪音测试”“iPhone 型号 + 测分贝”等模板页。先用表格、锚点或排查分支承接。
3. “卧室噪音怎么测”首先由房间场景页承接，不再写一篇功能相同的入门文章争夺意图。
4. 计算器页面自身解释公式、示例与假设，不额外拆一篇只为覆盖“分贝叠加公式”的薄文章。
5. 专业检测机构、投诉取证、App 下载、音频文件响度分析属于不同任务；首版不假装满足这些需求。
6. 新增 URL 前写明“与现有页面相比，多了什么输入、步骤、证据或结论”；没有明确答案则合并到现有页面。

这种归属方式也符合 Google 关于避免门页和低价值规模化内容的要求；具体页面划分是本项目的产品决策。[来源](https://developers.google.com/search/docs/essentials/spam-policies)

## 5. 页面结构与设计层级

所有界面遵循 [DESIGN_HIERARCHY.md](../../DESIGN_HIERARCHY.md)。复用字体、变量、控件和测量引擎；根据页面任务组织内容，不套同一组等宽卡片。

### 首页：工具就是首屏

- 主体：测量工作台。等待状态突出开始操作；运行状态突出读数、口径和趋势；结束状态突出结果理解及保存。
- 必要支持：输入来源、校准状态、有效时长与异常信息，靠近读数或设置区。
- 桌面沿用 V2 的测量区与设置区关系；手机优先显示操作、状态和核心读数，帮助按需展开。
- 工具下方依次安排简明使用步骤、准确性说明、三项场景操作说明、精选知识与真实常见问题。场景区直接展示房间、家电开关及开关窗的简短方法，不设置跳转或额外操作入口；独立场景页按下述发布条件单独评估。采用流程、文字分栏、对照表和条目导航表达各自关系。
- 未授权时不显示伪实时读数；示例必须显著注明。拒绝授权后仍能阅读全部静态内容。
- 候选 Title：`在线分贝测试与噪音观察工具 - 分贝测试`；候选 H1：`在线分贝测试`。英文用自然工具名称，避免堆砌同义词。

### 场景页：方法与工具一起完成任务

结构为：明确要比较的问题 → 固定条件 → 分步观察 → 嵌入同一测量组件 → 比较解释 → 方法局限 → 相关知识。

- 房间：记录位置、时段和干扰；卧室作为其中一个方法分支，不承诺后台整夜运行。
- 家电：记录关闭与开启状态、距离、档位和重复观察；不能把两次读数直接相减当作家电独立声级。
- 关窗：位置、声源与天气等条件变化需要记录；读数差不能自动换算成窗户的专业隔声指标。
- 同设备、同输入设置、同口径才能做有意义的比较；校准无效时恢复通用估算，并保留模型来源；旧相对记录不重新解释，也不与新估算混比。

条件没有固定距离的通用答案时，不编造一个适用于全部设备的标准。场景页尚无专属方法和可用操作能力时不发布。

### 知识页：先回答，再解释，再行动

标题优先使用用户会问的问题或明确任务，例如“网页是怎么测分贝的？”“麦克风打不开怎么办？”。避免让 dBFS、参考关系、口径等术语独立承担入口标题；必要术语保留在说明、正文定义与来源中。已有文章修改标题时保留 URL 与章节锚点，并同步双语、页面元数据与关键词映射。

正文顺序为：直接回答 → 适用条件 → 图表或实例 → 操作方法 → 常见误解 → 来源与更新时间 → 一个相关操作入口。

使用正文阅读栏、目录锚点、比较表和必要提示。短定义与长方法允许不同布局；不为凑字数添加重复段落，不设统一文章字数配额。分贝对照表不能声称扬声器可以准确重放某一环境分贝。

### 计算器页：输入和结果为主

先明确输入单位与假设，再给可编辑输入、结果及错误提示；随后解释计算过程和可验证例子。叠加计算采用有来源的适用公式，限定为可按能量叠加的非相干声源等条件；实现前另行验证数学、单位及边界。它不代替现场测量。

### 导航页与信任页

当前知识导航按“理解读数、查询声音参考、了解噪音与健康、解决使用问题”组织五篇文章，使用指南、工作原理和常见问题作为明确的帮助入口。桌面采用分类说明与文章摘要并列的开放目录，手机按分类、文章顺序阅读；后续实际场景和进阶方法仅在相关内容发布后加入。标签是筛选能力，初期不生成索引页。

关于页写明实际维护主体、产品目的、方法来源与使用说明；反馈方式仅在确认公开可用后展示，私有仓库不作为产品入口。隐私页与真实实现保持一致。未有的资质、团队、合作品牌和用户评价不作为装饰加入。

Lucide 图标用于操作、输入类型和提示角色；不用每段前加图标制造虚假层级。英文排版、移动端顺序与键盘操作均需单独验证。

## 6. 内容生产与维护体系

### 内容类型

| 类型 | 内容责任 | 证据与体验资产 | 主要下一步 |
| --- | --- | --- | --- |
| 工具 | 立即完成测量或计算 | 真实状态、输入校验、错误恢复、方法说明 | 完成一次操作 |
| 场景 | 在特定条件下完成观察 | 条件记录表、步骤、同口径比较、真实示例 | 按方法测量并保存 |
| 基础知识 | 解决读数理解问题 | 原始资料、示意图、明确术语 | 回到对应工具或校准 |
| 故障帮助 | 恢复当前任务 | 实际错误分支、浏览器实测记录 | 重试并成功开始 |
| 权威资料解读 | 正确理解适用范围 | 当前有效原文、地区、发布日期与复核者 | 选择适合的专业方法 |

首版沿用参考项目“类型化内容模块 + 构建生成静态正文”的方式，暂不增加 CMS 或 MDX 依赖。工具页、场景页和文章共享来源记录与关联配置，不共享一套万能正文结构。

每篇内容的实施字段应至少包括：`id`、`kind`、语言、路径、状态、Title、H1、description、摘要、章节、关联工具/内容 ID、来源、实际发布日期和修改日期。类型特有字段单独定义；不把文章 schema 强套到工具页。

工作流：

1. 在关键词映射中确认归属、读者任务与现有页面差异；记录需要验证的查询。
2. 查一手资料并完成真实操作。教程注明测试浏览器、系统及验证日期；示意数据注明性质。
3. 编写直接答案、方法、条件和下一步；涉及声音测量的公式与单位单独核对。
4. 核对内容、工具现状与双语含义；英文例子自然改写，不补不存在的地区法规。
5. 检查元数据、正文 HTML、内链、状态码及手机体验，再将对应语言标记为可发布。
6. 发布后根据真实查询、使用失败与反馈修订；只有实质内容变化才更新修改日期。

AI 可辅助提纲、整理与语言表达，来源核对和操作验证不能省略。作者署名反映真实参与者；没有审稿人就不填写虚构审稿信息。

健康与法律选题保持 P2：写明国家/地区、标准适用环境和时间口径，核验当前有效文本，并完成相关领域复核后才发布。不能拿某个阈值给所有房间、所有时间、所有测量口径判“超标”。现阶段只规划主题，不提供阈值结论。

## 7. 内链与多语言机制

- 首页连接已发布的指南、校准、准确性解释和少量高相关场景；不放全站关键词链接墙。
- 知识页从答案附近连接一个最适合的操作；正文再连接真正有帮助的解释，不把每篇文章链接到所有工具。
- 场景页连接同一个测量引擎及相应方法；工具页提供对应解释，建立双向路径。
- 导航、面包屑、正文关联入口使用真实可抓取链接。知识列表内容变多后采用静态分页，每页自有 URL；筛选不生成大量参数组合。
- `relatedIds` 代表候选关系。只渲染当前语言已发布的目标；未发布的主题不出现空链接。
- 内容语言使用 `zh-CN`、`zh-TW` 与 `en`；语言清单在 `src/lib/i18n/locales.ts` 维护。每个已发布页面自 canonical；不同语言不互相 canonical。
- 只有实际存在且内容对应的语言页才输出互相返回、包含自身的 `hreflang`；`x-default` 指向该主题的中文默认页。没有对应英文页时不生成英文占位页或错误 alternate。
- 语言切换优先到同主题；没有对应内容时提供目标语言首页。按用户要求，无语言前缀的已发布页面在浏览器首屏脚本中优先恢复手动偏好，否则按浏览器语言列表匹配，未知语言回退简体；明确的 `/en/`、`/zh-tw/` 链接保持其指定语言。不依据 IP 判断，不改写静态语言页的 canonical、hreflang 或正文；禁用 JavaScript 时仍可阅读 URL 对应的完整内容。实现边界见 [语言自动选择与偏好验证](../验证/语言自动选择与偏好验证.md)。

Google 要求语言版本之间的对应关系可相互验证；上线时从同一语言可用性数据生成 alternate，避免维护两份相互冲突的关系。[来源](https://developers.google.com/search/docs/specialty/international/localized-versions)

## 8. 技术 SEO 验收要求

| 项目 | 执行要求 |
| --- | --- |
| 正文 | 核心答案、标题、步骤、来源与链接存在于构建出的 HTML；不依赖授权麦克风或浏览器取数后才出现 |
| URL | 使用小写 kebab-case 和统一尾斜杠；唯一规范域名为 `https://fenbeiceshi.com`；HTTP 与 www 跳到同一路径规范地址 |
| 元数据 | 每页自然且独立的 Title、H1、description；不用关键词密度、固定字数或 meta keywords 作为验收指标 |
| canonical | 干净路径自引用；仅改变预设/来源追踪的参数版本归回同一正文页面；保留用户必要状态 |
| sitemap | 仅列实际发布、可索引、规范且返回 200 的 URL；更新日期对应实质修改；排除草稿与个人记录 |
| robots/noindex | 功能记录页及测试环境 noindex；生产内容不误拦资源；需要搜索引擎读取 noindex 的页面不能同时用 robots 阻断抓取 |
| 私人数据 | 不把录音、记录数值或设备标识放进公共 URL；noindex 不是隐私保护机制 |
| 状态码 | 不存在的路径返回真实 404；不通过首页回退返回 200；迁移 URL 使用明确的永久跳转映射 |
| 结构化数据 | 文章和适用子页提供真实 Article/BreadcrumbList；字段与可见内容一致，不虚构评分、资质和日期，不承诺富结果 |
| 性能 | 限定 Client Component 范围；音频处理和曲线在需要时启动；移动端避免布局跳动和非必要首屏资源 |
| 地域可达性 | 中文核心功能不依赖境外字体或第三方脚本才能显示；部署后从实际目标网络验证可达性和延迟 |

canonical、内部链接、跳转与 sitemap 应指向一致的规范地址。[来源](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

各搜索引擎的收录与排名仍须分别观察。Google 的技术建议不等于百度或必应的效果承诺；上线时按各自站长平台当前能力完成验证与提交，避免先接入不必要的推送依赖。

## 9. 发布批次与完成标准

批次代表依赖顺序，不是按日期或文章数量冲量。

| 批次 | 范围 | 发布前必须成立 |
| --- | --- | --- |
| P0：核心可用 | 中英首页、指南、工作原理、常见问题、校准、知识导航、基础文章、关于、隐私；本机记录为功能页 | 完整测量状态与正确口径、拒绝授权恢复、实际隐私行为、双语核心内容和静态 SEO 验收 |
| P1：任务扩展 | 中文场景导航及 3 个场景、3 篇深入帮助；独立叠加计算器完成后才开放工具导航 | 每个场景有独特方法和可用操作；计算公式已核验；英文内容按能力和需求分别进入此批或 P2 |
| P2：证据扩展 | 需要领域复核的知识、已证明有需求的英文场景、更多独立工具 | 一手来源与适用范围已复核；查询或反馈支持独立意图；新增页面有实际价值 |

当前本地实现简体、繁体和英文各 41 个可索引页面，共 123 个 URL；另有三个 noindex 本机记录页，总计 126 个三语 URL。其中 28 个分贝详情主题新增 84 个三语 URL，按既有 31 项声音的单值或完整范围组织，独立场景问题与条件见 [实现说明](./分贝详情页说明.md) 和 [验证记录](../验证/分贝详情与行内链接验证.md)。繁体是现有页面的对应语言，沿用同一主题、来源与测量口径，不新增地区法规或医疗结论。维护与验证见 [繁体中文支持验证](../验证/繁体中文支持验证.md)。新增工作原理和完整常见问题各有明确任务及双语正文，基础文章继续负责准确性、dBFS 与声压级差异、声音对照、麦克风排查及健康知识。页面注册是实现依据，生产仍未部署；后续候选页按原门槛发布。

首版保留中英文完整工具能力；P1 场景中文先行，英文基础解释优先。P2 中国标准解读目前只规划中文，不强行制造一个全球英文“噪音标准”页面。

## 10. 如何判断工程营销是否有效

首要观察“搜索访问是否完成了有意义的任务”，同时看内容与工具之间的实际流转。

| 层次 | 建议观察 | 决策用途 |
| --- | --- | --- |
| 搜索触达 | 各语言/搜索引擎的有效收录、查询、展示、点击、CTR | 修订意图归属、标题与内容覆盖 |
| 工具入口 | 内容到操作入口的点击率、操作开始率 | 判断内容是否解决了实际问题 |
| 使用质量 | 授权请求/结果、实际取到有效数据后的开始、结束原因、校准完成、摘要保存 | 定位设备兼容、权限、误解与流程问题 |
| 持续价值 | 主动复测、比较使用、回访；优先采用汇总或匿名方式 | 决定后续工程投入 |

建议事件：`tool_cta_click`、`permission_request`、`permission_result`、`measurement_start`、`measurement_end`、`calibration_complete`、`record_save`、`comparison_complete`、`calculator_submit`。尚未实现的能力不发对应事件。

授权弹窗出现不等于测量开始。未取得有效样本、被中断或仅看示例的会话不能计算为完成；记录相应原因类别。统计中只保留必要的页面 ID、语言、模式和时长区间，不发送原始音频、精确记录、设备 ID 或可识别用户的错误原文。实际统计工具接入时再评估依赖和隐私影响，并同步隐私页。

不预设流量、排名或转化率承诺。首轮真实数据作为基线；有展示但低点击检查标题与意图，有访问但无法开始检查权限与兼容性，有开始但不保存则先核实保存是否对该任务有价值。

## 11. 竞品到来后的验证方式

逐个记录：URL、语言与目标用户、实际可用功能、首屏任务、权限/校准口径、独有方法、内容栏目、内链、索引结构、回访理由及可验证证据。浏览器真实体验和搜索样本分别记录，不从外观或搜索片段推断准确性与流量。

关键词逐批验证：选择目标市场与设备 → 查看当前结果类型及用户任务 → 检查候选词是否同意图 → 结合站长平台或授权关键词数据 → 调整归属和批次。没有数据的项继续标记候选，不能补写搜索量或难度。

新增、合并或删除路由时，同步 JSON 映射、语言关系、关联 ID、导航与发布记录；如果 URL 已公开，再补跳转计划。竞品分析可以修订本规划，但不能以竞品的未经验证声明替代本产品的能力验证。
