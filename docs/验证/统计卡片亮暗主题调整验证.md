# 统计卡片亮暗主题调整验证

日期：2026-10-19。范围为首页最低、最高、平均三个统计卡片的颜色层级和待测提示；只更新本地实现。

## 调整结果与文件职责

- `src/features/sound-meter/session-stats/index.module.css`：前三个卡片改用主题主表面和加强边界，标签、单位与说明使用 `--text-body`。亮色数字使用保留原色相的高饱和文字色阶，加深黄绿段而不混入正文灰色或降低透明度；暗色数字沿用原量级色。顶部细线继续使用仪表与色带的原色，图标保留原有混色。无数据时数字回退 `--ink`，图标使用品牌色与主文字色混合，不伪造声级。
- `src/features/sound-meter/session-stats/index.tsx`：数字按各自读数映射到局部文字色阶；从现有 `frame` 推导待测状态，保留空值和单位，并显示等待提示。没有新增状态、Effect 或客户端边界。
- `src/features/sound-meter/palette.ts`：`readingColor` 接受可选的五色调色板，两套色阶复用同一连续插值；默认参数保留仪表、色带等现有调用的配色。
- `src/features/sound-meter/copy.ts`：新增中文“等待测量”和英文“Awaiting data”；待测提示使用固定 14px，手机也显示。有数据时恢复原有观察范围和采样说明。
- `design/noise-estimate-v1/design-spec.json`：同步统计颜色职责和本次截图入口；量级映射、测量算法、记录格式与第四个时长卡片的专属样式保持原有实现。

统计仍为同级摘要，沿用桌面四列、手机两列，不增加容器、交互或全局样式。样式留在相邻 CSS Module，未增加依赖。应用 `vercel-react-best-practices` 的渲染期间推导状态与 CSS 类职责规则，并按 `simplify` 复核本轮代码。

本轮保存并查看 7 个状态截图，同时读取 DOM 计算样式，核对数字计算颜色与 `--stat-number` 指定的主题色阶及插值一致。演示中切换主题后，会话继续更新。退出演示后，三个卡片恢复中性空值、等待提示和中性顶部边界。恢复了验证前的亮色外观与默认浏览器视口。

按实际计算颜色与卡片纯色背景计算 sRGB 对比度；有数据数字的全色带最低值另以源码颜色按 0–120、每 0.1 dB 采样计算：

| 文字角色                      | 亮色    | 暗色    |
| ----------------------------- | ------- | ------- |
| 无数据占位                    | 13.08:1 | 13.08:1 |
| 有数据数字（色阶计算最低值）  | 4.61:1  | 4.89:1  |
| 标签、dB 单位、说明及等待提示 | 5.58:1  | 8.19:1  |

实际演示截图中的数字对比度为亮色 4.62–4.69:1、暗色 9.17–10.01:1；颜色随各自读数更新。亮色五个锚点的 HSL 饱和度约为 90%，与原锚点的色相差小于 0.14°；保留绿、黄绿、金黄、橙、红的顺序并提高白底对比度。无数据暗色占位及第四个时长卡片沿用前轮浏览器的基线验证，本轮未改动其专属样式。五个色点和数学计算方法见 [number-palette-checks.json](../../design/noise-estimate-v1/session-stats/number-palette-checks.json)，这些是显示颜色检查，不代表声学精度验证。

第四个时长卡片在两种主题下的背景、边界、数值、标签、图标和说明样式，与调整前读取的计算值一致。网格行高继续随内容自然伸展。

截图与计算结果位于 [统计卡片验证目录](../../design/noise-estimate-v1/session-stats/)，本轮场景清单与颜色结果见 [contrast-browser-checks.json](../../design/noise-estimate-v1/session-stats/contrast-browser-checks.json)；既有截图保留为早期验证记录。
