# 语言下拉菜单验证

日期：2026-10-21。本轮承接繁体中文支持，按用户要求将页头与手机菜单中的语言入口改为自定义下拉框。

2026-10-22 增加首次自动识别与手动偏好保存，后续行为及验证见 [语言自动选择与偏好验证](./语言自动选择与偏好验证.md)。

## 修改范围

- `src/components/language-switch/` 使用按钮与自定义 `listbox`，固定显示「简体中文」「繁體中文」「English」，默认选中当前语言并显示勾选标记；选择后沿用 `languageHref` 前往当前主题的对应语言，选择当前项只收起菜单。
- 服务端输出当前名称与隐藏的三项列表，先禁用按钮，水合完成后启用，避免选择事件先于路由监听绑定。就绪状态继续由 `useSyncExternalStore` 提供，不增加全站客户端逻辑。
- 沿用已有麦克风下拉控件的交互模式，焦点留在触发按钮，以 `aria-activedescendant` 标明高亮项。方向键循环选择，Home / End 跳至首尾，Enter / 空格确认，首字定位支持 English；Esc、Tab、失焦或点击外部收起菜单。列表与选项 ID 由 `useId` 生成，桌面、手机各自关联。
- `src/lib/i18n/locales.ts` 维护完整语言名称，移除原来链接专用的切换标签。canonical、hreflang 和三语路由保持原有关系。
- 下拉框样式放在相邻 CSS Modules，复用麦克风控件的圆角、语义颜色、固定 12px 字号和 Lucide 箭头／勾选标记。展开时旋转箭头，减少动画设置下停用过渡；亮暗主题均使用现有变量。
- 桌面列表向下展开，手机抽屉内向上展开，避免底部裁切。Esc 首先收起语言列表，再次按下才关闭手机菜单；焦点循环使用按钮和链接。底部说明与控件分两行，761–900px 页头保留紧凑间距。
- `scripts/check-export.ts` 检查所有页面的桌面、手机自定义控件、默认收起状态、三项完整名称、lang、可访问关联及当前选中项，并禁止回退到原生 `select`。

文案与样式均复用既有组织方式，未新增依赖。沿用已读取的 React 最佳实践、文档维护与 simplify 技能，复核了组件职责和客户端范围。

## 实际验证

- `rtk npm run check`：格式、lint、strict 类型、113 项测试、内容、静态构建和产物检查通过；42 个页面、39 个 sitemap URL、1461 条内部链接与锚点通过。
- `rtk git diff --check`：通过。npm 仍提示本机既有的 `Unknown user/env config "home"`，未修改全局配置。
- 内置浏览器实测 1280×720、761×800 桌面，以及 320×740 手机视口。761px 页头与 320px 手机菜单无横向溢出，语言名称完整可见。
- 展开下拉框，确认三项名称及当前项勾选。分贝对照页在英文、繁体、简体之间连续切换，均保留 `/knowledge/decibel-chart/` 主题；手机以 Home、ArrowDown、Enter 切换至繁体后，进入对应页面，导航抽屉收起。
- Home / End 首尾定位、方向键循环、空格打开、选择当前项、点击外部与 Esc 收起均通过。手机菜单关闭按钮按 Shift+Tab 到达语言按钮，语言按钮按 Tab 回到关闭按钮；第一次 Esc 仅关闭语言列表，第二次关闭手机菜单并恢复入口焦点与背景滚动。
- 320px 手机弹层范围为 x=148–300、y=540–670，完整位于抽屉内；三项均可见。亮暗主题下验证名称、选中态及菜单边界。
