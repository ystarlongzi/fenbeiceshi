- 提交前的 `rtk proxy git diff --cached --check` 会报告上游编码器和许可原文自带的尾随空格；按原文件逐字节分发约定保留。排除 `public/vendor/lamejs/**` 后的暂存区空白检查退出 0，自有代码无此问题。

## 浏览器与文件验收

使用 Codex 内置浏览器和独立本机测试源 `http://127.0.0.1:3188`，将测试夹具的 `getUserMedia` 替换为 440 Hz 合成音源；实际应用仍走 MediaStream → 共用 AudioContext → AudioWorklet → PCM / WAV → MP3 Worker 路径。不打开真实麦克风，不把合成结果保存进本机摘要。测试辅助 HTML 只临时放在 `out/`，验收后已移除，专用 3188 服务已停止。

| 范围                   | 实际结果                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------- |
| 默认关闭、演示         | 初始无采集请求；演示无音轨、录音、音频下载或 Object URL                                                  |
| 正常录音               | 结束后能播放，音频时间向前推进；生成 MP3 后出现 MP3 和 PCM 下载入口                                      |
| 授权等待取消、迟到授权 | 迟到的合成音轨立即结束，音频上下文关闭，无录音和临时 URL                                                 |
| 拒绝权限               | 明确显示麦克风错误，无录音                                                                               |
| 录音不可用             | 故意移除测试环境的 AudioWorkletNode 后显示就近错误；分贝测量继续                                         |
| 输入中断               | 停止音轨与上下文，保留有效结果及已录音频                                                                 |
| 达到上限               | 夹具将上限缩短至 48000 帧；录音精确保留 1 秒并提示，测量与输入仍运行。未把此项描述为实机连续录满 10 分钟 |
| 关闭录音后再次测量     | 仍保留上一段录音，其下载 URL 不变；不创建新录音                                                          |
| 清除与页面导航         | 清除后 3 个播放 / PCM / MP3 Object URL 全部撤销；离开到隐私页再回首页，无旧录音，默认关闭                |
| 中文手机               | 应用视口 390×844；录音、回放、MP3 生成、下载按钮换行与说明正常，无横向溢出                               |
| 英文手机暗色           | 应用视口 320×844（外部浏览器 320×740）；按钮、时间、格式与长说明可读，无横向溢出                         |
| 独立预览页             | 更新 `http://127.0.0.1:3100/` 后检查默认开关、切换与复位；未采集真实音频，控制台 warn/error 为 0         |

辅助页切换 iframe 时曾捕获一条未标明来源的 MutationObserver 错误，另有故意模拟不支持录音产生的预期错误日志。未在独立预览页复现前者，不声称所有辅助测试过程控制台始终无误。

- `rtk proxy ffmpeg -v error -i /Users/liucai/Downloads/fenbeiceshi-2026-10-20T00-52-27-409Z.mp3 -f null -`：退出 0，实际 MP3 解码无错误。

## 体积与职责复核

录音逻辑留在 `src/features/audio-recording`，选项和结果的样式位于相邻 CSS Modules；`CaptureSession` 只提供可选采集分支。没有增加全局组件样式或改动摘要结构。自有新增源码单文件最高为结果组件约 179 行有效代码；采集 Hook 约 220 行，函数未接近 300 行上限。

独立编码器原文件 259508 字节（本机 gzip 66779 字节），SHA-256 为 `1c5f944911ccf2f6e29ab36c2e568363210ab16f50c0d76077060f40ecf91d28`。仅生成 MP3 时同源加载，不进入首页初始编码器载荷。完整上游源码以固定提交归档，不参与运行时加载。

编码器发行文件有 9650 个物理行，作为未修改第三方发行资产保留，是 700 行规则的明确例外；不拆分或格式化第三方实现，避免破坏原始一致性及可替换分发。许可证、源码和替换方式保留在 `public/vendor/lamejs/`。本轮应用 React 最佳实践、依赖评估、lint/format、文档更新与 simplify 技能。
