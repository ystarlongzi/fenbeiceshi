## 浏览器与文件验收

使用 Codex 内置浏览器和独立本机测试源 `http://127.0.0.1:3188`，将测试夹具的 `getUserMedia` 替换为 440 Hz 合成音源；实际应用仍走 MediaStream → 共用 AudioContext → AudioWorklet → PCM / WAV → MP3 Worker 路径。不打开真实麦克风，不把合成结果保存进本机摘要。测试辅助 HTML 只临时放在 `out/`，验收后已移除，专用 3188 服务已停止。

## 体积与职责复核

录音逻辑留在 `src/features/audio-recording`，选项和结果的样式位于相邻 CSS Modules；`CaptureSession` 只提供可选采集分支。没有增加全局组件样式或改动摘要结构。自有新增源码单文件最高为结果组件约 179 行有效代码；采集 Hook 约 220 行，函数未接近 300 行上限。

独立编码器原文件 259508 字节（本机 gzip 66779 字节），SHA-256 为 `1c5f944911ccf2f6e29ab36c2e568363210ab16f50c0d76077060f40ecf91d28`。仅生成 MP3 时同源加载，不进入首页初始编码器载荷。完整上游源码以固定提交归档，不参与运行时加载。

编码器发行文件有 9650 个物理行，作为未修改第三方发行资产保留，是 700 行规则的明确例外；不拆分或格式化第三方实现，避免破坏原始一致性及可替换分发。许可证、源码和替换方式保留在 `public/vendor/lamejs/`。本轮应用 React 最佳实践、依赖评估、lint/format、文档更新与 simplify 技能。
