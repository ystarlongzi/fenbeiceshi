# 工程与部署说明

更新：2026-10-24。本文描述仓库已经实现的工程入口；服务器开通、GitHub 配置与实际生产验收按 [服务器部署](../部署/服务器部署.md) 执行。仓库内的部署能力与生产环境是否已启用分别记录，实际结果见 [部署工程验证](../验证/部署工程验证.md)。

## 架构与运行条件

本站使用 Next.js App Router、React、TypeScript strict、npm 与 CSS Modules。`next.config.ts` 已设置 `output: "export"`、`trailingSlash: true` 和静态图片输出。文章、帮助、来源与 SEO 在构建时生成 HTML，测量、录音、主题及本机记录在必要的客户端子树运行。

构建机要求 Node `>=24.11.0 <27`，GitHub Actions 使用 Node 24。生产服务器只提供静态文件，不运行 Next.js 服务，不需要安装 Node 或数据库。麦克风、原始音频、报告及录音存储在用户浏览器中；服务端发布不迁移用户记录。

当前规范域名为 `https://fenbeiceshi.com`，简体中文在根目录，繁体中文在 `/zh-tw/`，英文在 `/en/`。真实路由由 `src/lib/routing/pages.ts` 注册，语言由 `src/lib/i18n/locales.ts` 维护；候选关键词文件不参与页面发布。各页的正文、canonical、hreflang 和 sitemap 随构建输出，三个记录页 noindex。未知路径使用应用生成的统一 `404.html`，保持 HTTP 404。

## 目录职责

| 目录                               | 职责                                                        |
| ---------------------------------- | ----------------------------------------------------------- |
| `src/app/`                         | 路由、根布局、全局基础样式、metadata、sitemap 与 robots     |
| `src/features/`                    | 测量、读数修正、录音、报告及本机记录等独立功能              |
| `src/components/`                  | 确实跨功能共享的组件；专属 CSS Modules、Hook 和测试就近维护 |
| `src/lib/content/`                 | 类型化静态正文、声音参考及三语文案                          |
| `src/lib/routing/`、`src/lib/seo/` | 发布页面注册与派生的 SEO 数据                               |
| `public/`                          | 图标、AudioWorklet、编码器及必要许可证                      |
| `scripts/`                         | 本地与 CI 共用的测试、内容、导出和部署变更检查              |
| `deploy/`                          | 本站打包、SSH、服务器初始化、发布、回滚、Nginx 模板与测试   |
| `.github/workflows/`               | 项目检查、生产发布和手动回滚                                |
| `docs/`、`design/`                 | 产品、工程、运维、设计依据与实际验证记录                    |

组件样式使用相邻 CSS Modules，`globals.css` 只承载框架入口、基础元素及公共变量。页面默认服务端组件；功能和内容变更沿用根目录 AGENTS.md，不为部署修改页面职责或浏览器存储结构。

## 本地命令

```sh
npm ci
npm run dev
```

开发服务为 `http://127.0.0.1:31031`。静态预览先运行构建，再启动预览：

```sh
npm run build
npm run preview
```

两个服务不能同时占用同一端口，预览可通过 `FENBEI_PREVIEW_PORT` 改端口。端口改变也会改变浏览器存储的 origin，已有记录不会自动迁移。预览返回真实 404 和同源麦克风响应头，只用于本机检查。

| 命令                                                              | 实际职责                                                       |
| ----------------------------------------------------------------- | -------------------------------------------------------------- |
| `npm run format:check`                                            | Prettier 检查，不改写                                          |
| `npm run lint`                                                    | ESLint，警告阻断                                               |
| `npm run typecheck`                                               | strict 类型检查                                                |
| `npm run test`                                                    | 应用算法、状态、音频、记录与报告测试                           |
| `npm run test:deploy`                                             | 部署参数、凭据、初始化失败恢复、工作流和 Shell 语法测试        |
| `npm run test:content`                                            | 页面注册、三语内容、来源、关联与发布一致性                     |
| `npm run build`                                                   | 生成 `out/`                                                    |
| `npm run test:export`                                             | 静态 HTML、正文、链接、canonical、语言关系、sitemap 与 noindex |
| `npm run check`                                                   | 顺序执行以上检查，包含构建与静态产物检查                       |
| `npm run test:deploy:integration`                                 | 临时 Linux/root 环境中的真实 Nginx/TLS 发布与回滚演练          |
| `npm run deploy:pack -- --release <版本号>`                       | 校验 `out/`，生成版本包与 SHA-256 文件                         |
| `npm run deploy:setup -- --bootstrap`                             | 准备服务器工具、本站 DNS-01 证书、续期与 Nginx 配置            |
| `npm run deploy:static -- --artifact <包路径> --release <版本号>` | SSH 上传、校验、切版、健康检查与失败恢复                       |

格式、lint、类型和构建沿用现有工具；本次部署实现仅使用 Node 内置模块，不新增 npm 依赖。Shell 脚本要求 Linux/GNU 工具；集成测试仅在可丢弃的容器或 Actions runner 执行，入口会核验域名仅解析到回环地址。可复现的容器命令见部署手册。

## GitHub Actions

- `check.yml`：所有 Pull Request、非 main 分支推送以及手动检查，执行 `npm ci` 和 `npm run check`；部署相关文件变化时追加 Linux 集成演练。
- `deploy.yml`：main 推送或在 main 手动运行，使用 `production` 环境；同一 job 内完成检查、必要的 Linux 演练、打包和 SSH 发布。只有手动勾选 `prepare_environment` 才初始化服务器工具与证书。
- `rollback.yml`：在 main 手动填写服务器保留的版本号，使用同一个 production 环境和生产并发组，直接执行 SSH 回滚。回滚只依赖 Node 内置模块，无须重新安装 npm 依赖或构建网页。

发布和回滚共用 `fenbeiceshi-production` 并发组且不自动取消运行中的操作；远端另用文件锁防止本机命令与 Actions 并发。官方 Actions 固定完整提交 SHA，checkout 不保留 Git 凭据，工作流只申请 `contents: read`。

`SSH_KNOWN_HOSTS` 和本机的 `SSH_KNOWN_HOSTS_FILE` 均为可选。提供文件时使用严格核验；省略时使用 `StrictHostKeyChecking=accept-new`，首次连接自动记录主机公钥，已有记录不匹配时仍拒绝连接。Actions 的记录仅保留在当前 runner。

构建后的 `out/` 在当前 runner 校验并直接打包，通过 SSH 标准输入传输；不上传或跨 job 下载 GitHub Artifacts。npm cache 只缓存依赖。源站保留当前版本和最多两个回滚版本，共享哈希资源至少提供七天缓冲，并继续保留回滚版本引用的资源。

## 发布边界

服务器配置、密钥、DNS Token 和本机部署配置均不进入网页或发布包。本站域名和部署目录有双重白名单，Nginx 配置、证书、日志、ACME 目录与 Cloudflare zone 均有独立路径。初始化需要 root，日常发布仅需本站目录的写权限及相应的 SSH 登录权限。

Nginx 为 HTML 设置及时重验证、为哈希资源设置长缓存，为 `/_release.txt` 设置 `no-store`。主文档必须保留 `Permissions-Policy: camera=(), microphone=(self), geolocation=()`；这允许请求同源麦克风，用户仍须授权。HTTPS、Cloudflare Full (strict)、实际 Cache Rules、域名跳转和真实设备权限需要在生产环境另行验收。

浏览器记录当前支持封装版本 1、2、3；旧应用拒绝版本 3 并保留原数据。回滚网页不会降级或清空存储，涉及跨存储版本回退前应导出重要报告。迁移细节见 [噪音估算口径](../产品/噪音估算口径.md) 和 [即时读数修正验证](../验证/即时读数修正验证.md)。

后续请求时 SSR、登录、云端存储或音频上传等需求，需要另行设计服务端能力，不能沿用静态部署假设。依赖审计与工具选型见 [依赖与检查配置](./依赖与检查配置.md)，首次上线、日常发布、故障处理和回滚的完整操作见 [服务器部署](../部署/服务器部署.md)。
