| Prettier 3.9.10                         | 采用；官方包 MIT，统一 TSX、CSS、JSON、文档与配置格式                                               |
| 图表、动效、状态管理和图标 React 包     | 不新增；SVG 仪表与趋势、CSS 状态、局部 Hook 与固定来源 Lucide 资产满足首版                          |
| Vitest/Jest                             | 首版不新增；Node 内建测试运行器及类型剥离运行纯 TypeScript 测试，减少依赖图                         |

Next.js 官方包体积包含构建工具与各运行时，npm 元数据解包体积约 183.6 MiB，不等于浏览器传输体积。站点导出静态产物；客户端只带测量、设置与记录必需代码，不序列化全部文章正文。

TypeScript 为 Apache-2.0，所选 ESLint、Prettier 与类型包为 MIT。安装后以锁文件固定传递依赖，并运行 npm audit；实际审计、依赖树及构建结果记录在验证文档，不能把版本核对当作漏洞审计。

## 配置边界

Node 要求 `>=24.11.0 <27`，CI 使用 Node 24，当前本机为 26.5.0。类型包采用 Node 24 基线，避免依赖只存在于更高版本的运行时 API。

`format:check`、`lint`、`typecheck` 不改写；`format` 与 `lint:fix` 明确改写。格式范围包含应用、脚本、配置、README、AGENTS 与本次文档；历史设计资产和规划通过 `.prettierignore` 明确排除，不进行全库迁移。锁文件由 npm 生成。

测试重点为 RMS/能量统计、校准条件、记录输入约束和异步取消；不为静态文案写镜像测试。内容检查核对真实路由、语言关系、关联与内容字段；`test:export` 检查实际构建 HTML、语言、正文、链接和 sitemap。构建和生成类型按顺序执行，避免共同写入 .next 的检查竞争。

中英文采用分别输出 `html lang` 的根布局；未知路由使用 Next.js `global-not-found`，需要显式启用仍属实验性的 `experimental.globalNotFound`。已核对官方文档并验证静态导出和 404；框架升级时应继续检查该配置，不能假定实验接口永远兼容。[全局 404 文档](https://nextjs.org/docs/app/api-reference/file-conventions/not-found)

## 2026-10-17 实际审计

- `npm audit --omit=dev --registry=https://registry.npmjs.org --fetch-retries=1 --json`：退出 0，生产依赖已知漏洞为 0。
- 完整 `npm audit --registry=https://registry.npmjs.org --fetch-retries=1 --json`：退出 1，5 个 high 条目来自同一上游问题的传递影响：`eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces@3.0.3`。
- [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) 指向深层 glob 模式导致的栈耗尽；核对时官方尚无已发布补丁。它位于本机/CI 的开发检查链，静态浏览器产物不包含该工具链，应用也没有接收访客 glob 输入的接口；这不等于开发链已消除风险。
- npm 建议降级 `eslint-config-next` 到 14.2.35，属于跨主版本回退，与当前 Next.js 16 配套规则不一致；本次没有自动降级、隐藏审计或加入未经验证的 override。后续依赖更新时复核官方修复与配套版本。

本机 npm 配置还产生既有 `home` 配置警告；没有为本站修改用户全局配置。安装器提示 `unrs-resolver@1.12.2` 的 postinstall 不在本机 allowScripts 白名单中；没有扩大脚本授权，实际 lint 与构建已经通过。

首次交付的实际命令、浏览器范围和未验证项见 [首版验证记录](../验证/首版验证记录.md)。

官方依据：[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports)、[npm 官方仓库](https://registry.npmjs.org/)、[Node 测试运行器](https://nodejs.org/api/test.html)。首次使用时已查询具体包版本、engines、peerDependencies 与许可证。

## 2026-10-20 同步录音依赖

新增并固定 `@breezystack/lamejs@1.2.7`，不升级既有包，无生产传递依赖、无安装脚本。PCM 采集、播放包装和下载使用 Web Audio / AudioWorklet / Blob；MP3 为本机 Worker 编码。

| 候选                      | 优点                               | 风险与成本                                                     | 决策                                   |
| ------------------------- | ---------------------------------- | -------------------------------------------------------------- | -------------------------------------- |
| 原生 MediaRecorder        | 无新增依赖                         | 可用容器/编码需逐浏览器探测，不能保证用户要求的 MP3 与原始 PCM | 不作为本次格式方案                     |
| 自行实现 MP3 编码         | 无库依赖                           | 编码复杂、质量与兼容性验证成本高                               | 不采用                                 |
| FFmpeg / WASM 转码        | 格式丰富                           | 下载、初始化、内存和部署要求超出两种输出的需求                 | 不采用                                 |
| 原始 lamejs 1.2.1         | 体积有限、本机编码                 | 原包模块引用问题，ESM 与类型适配成本较高                       | 不采用                                 |
| @breezystack/lamejs 1.2.7 | 修正引用、ESM / TS、无生产传递依赖 | LGPL-3.0；最近版本发布于 2023-10-17，不能描述为活跃维护        | 采用，独立可替换分发，并补实际编码测试 |

2026-10-20 核对 npm 官方仓库版本、时间、依赖、许可证和包完整性，安装使用 `npm install --save-exact @breezystack/lamejs@1.2.7 --ignore-scripts --registry=https://registry.npmjs.org --fetch-retries=1`，由 npm 更新锁文件。`npm audit --omit=dev --registry=https://registry.npmjs.org --fetch-retries=1 --json` 退出 0，生产已知漏洞为 0；完整 audit 退出 1，仍为原有 ESLint 链的 5 个 high 条目，未扩大变更进行跨主版本回退。当前 npm 仍报告既有的用户 `home` 配置警告。

编码器不进入首页或应用 Worker 包，在生成 MP3 时按同源 URL 动态加载 `public/vendor/lamejs/lamejs.js`。库保持原文件，可直接替换而无需重新构建应用；目录附 LGPL / GPL 全文、上游说明、固定源码归档及替换方法，隐私说明与结果区给出声明入口。自动测试核对分发文件与锁定安装的字节一致，避免升级依赖后遗留旧分发文件。只将此第三方目录从 Prettier / ESLint 排除；本地录音源码与工作线程继续接受现有检查。

独立临时目录的 `npm ci --ignore-scripts` 已验证清单和锁文件可完成干净安装。发行文件约 259.5 kB，gzip 约 66.8 kB，只在生成 MP3 时加载；保留原文件的 9650 物理行属于第三方资产的明确规模例外，自有实现按职责拆分。

官方依据：[fork 文档与修复范围](https://github.com/gideonstele/lamejs)、[固定提交源码](https://github.com/gideonstele/lamejs/tree/1fb0ef5fa177413107e2e107d054a9b994e3f79c)、[原作者用法与许可证](https://github.com/zhuker/lamejs)、[MediaRecorder 格式探测](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)、[AudioWorklet 逐块处理](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletProcessor/process)。静态模块的实际体积、检查及浏览器范围见 [同步录音验证](../验证/同步录音验证.md)。

## 2026-10-21 IndexedDB 测试依赖

线上存储使用浏览器原生 IndexedDB，不新增运行时依赖。测试固定 `fake-indexeddb@6.2.6`，用于现有 Node 测试入口执行真实事务 API 的回滚、并发、清理与容量用例；浏览器持久化与下载另做实际验证。

| 方案                | 取舍                                                     | 结论                   |
| ------------------- | -------------------------------------------------------- | ---------------------- |
| 仅浏览器手测        | 无依赖，但 CI 无法回归并发、配额和中止场景               | 保留作补充验证         |
| 自写 IndexedDB mock | 需自行模拟事件顺序及事务回滚，容易测到错误语义           | 不采用                 |
| fake-indexeddb      | 无运行依赖，复用原生 API；仍不能替代真实浏览器磁盘与配额 | 仅加入 devDependencies |

官方 npm registry 核验版本、Apache-2.0、Node ≥18（兼容项目 ≥24.11）、无传递运行依赖，解包 490834 字节，无 install/postinstall；最近包更新时间为 2026-10-16。依据：[上游说明](https://github.com/dumbmatter/fakeIndexedDB)、[npm 包](https://www.npmjs.com/package/fake-indexeddb)。锁文件仅增加该包。完整 `npm audit --registry=https://registry.npmjs.org --json` 仍有既有 ESLint／braces 链 5 项 high，新增包未出现在漏洞树；未为本功能更改工具链。镜像 registry 不提供 audit API，审计使用官方 registry。
