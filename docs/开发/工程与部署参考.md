## 2. 首版架构选择

建议采用 **Next.js 构建静态页面 + 浏览器本机音频处理 + Nginx 提供文件**。文章、指南、场景方法和工具说明在构建时形成完整 HTML；测量、曲线、校准和本机记录是局部客户端交互。

这种模式可复用现有服务器的静态部署能力，也能让内容先于麦克风授权呈现。静态导出不需要为每次页面访问运行 Node 服务；新文章或内容更新通过重新构建发布生效。[Next.js 官方说明](https://nextjs.org/docs/app/guides/static-exports)

实施配置方向为 `output: "export"`、`trailingSlash: true`。构建输出为 `out/`；动态内容路由在构建时穷举。浏览器 API 仅在浏览器运行阶段访问。

边界：没有请求时 SSR、ISR、Server Actions 或动态 API 服务。登录、云端记录、上传音频、在线 CMS 预览等新需求到来时另行评估运行时，不把它们伪装成静态功能。安全响应头和永久跳转由 Nginx/Cloudflare 层配置，不能依赖静态导出不支持的 Next.js 运行时设置。

首版不引入 Docker、数据库、全站状态管理、MDX 或 CMS。局部状态先留在功能内；确实跨功能复用时再提取。所有后续依赖变更依照根目录 AGENTS.md 评估。

## 3. 目录与样式职责

```text
src/
├─ app/                         路由、layout、metadata、静态页面与 sitemap/robots
│  └─ globals.css               框架入口、重置、全局元素与公共设计变量
├─ components/                  站点外壳、导航等确实共享的展示组件
├─ features/
│  ├─ sound-meter/              麦克风生命周期、信号处理、状态与测量界面
│  ├─ calibration/              参考关系、有效条件与校准界面
│  ├─ records/                  本机摘要存储、查询与比较
│  └─ decibel-addition/          P1 独立计算器
├─ lib/
│  ├─ content/                  类型化文章/场景模块、来源与内容索引
│  ├─ routing/                  页面注册、已发布语言与路由关系
│  └─ seo/                      元数据、canonical、alternate 与结构化数据
└─ styles/                      仅在需要时存放独立的公共主题资源
public/                         图标、静态示意图与公开资源
scripts/                        本地与 CI 共用的检查入口
deploy/                         本站独立的打包、发布、健康检查与回滚
docs/                           产品、工程、部署与验证文档
```

业务组件使用 `kebab-case/index.tsx`，有专属样式时放同目录 `index.module.css`；所属 Hook、辅助逻辑和测试相邻维护。Next.js 路由仍使用框架命名。纯算法与存储适配可以是功能目录下的独立 TypeScript 文件，不为每个函数创建组件目录。

CSS Modules 是首版采用的组件样式方案；不把页面布局放入 globals.css，不混入另一套样式系统。公共颜色、间距、字体与状态变量统一维护。正文、测量工作台、场景步骤和计算器各自遵循任务层级，不抽象成万能卡片组件。

页面与正文默认保持 Server Component；需要音频、事件或本机存储的子树才使用 Client Component。不得把整篇文章或全站 layout 因一个交互入口改成客户端组件。实现 React/Next.js 代码前仍需按 AGENTS.md 读取相关技能。

## 4. 内容与多语言实现约定

- 先参考 `src/lib/articles/` 的类型化模块方式，再按本文目录调整职责；不整库复制屏幕测内容。
- [关键词映射](../产品/页面与关键词映射.json) 是策划资料，所有条目当前都是候选；运行时页面注册必须区分每种语言的草稿、复核与已发布状态。
- 路径、语言可用性、标题、关联 ID 和发布状态有单一来源；metadata、sitemap、导航与语言切换从该来源派生。
- 不照搬参考项目“每个页面必有中英两份”的假设。本项目存在只规划中文的主题，且两种语言可分批发布。
- 当前实际实现支持根目录简体中文、`/zh-tw/` 繁体中文与 `/en/` 英文，每种语言 14 个页面。`src/lib/i18n/locales.ts` 统一维护语言、前缀及区域格式，`text.ts` 定义显式三语文案；正文与帮助静态输出，仪表、录音和报告文案仍靠近所属功能，不加入运行时转换依赖。三语共用原有浏览器记录，不迁移或改写用户输入。详见 [繁体中文支持验证](../验证/繁体中文支持验证.md)。
- 首阶段把正文放在类型化内容模块中；不要让客户端筛选组件携带所有文章全文。
- 发布/修改日期来自实际编辑记录；重新构建不自动刷新全部日期。引用原始资料、示例性质和验证环境。
- 每个 URL 只满足其明确任务；场景组件复用测量能力，但正文条件与操作步骤要独立成立。

## 5. 同一服务器上的隔离方案

下表是本项目拟定命名，尚未在服务器验证或创建。实施前确认目录未被占用、现有 Nginx 组织和发布权限，再落实相应值。

| 项目 | 本站拟定值/约束 |
| --- | --- |
| 规范域名 | `fenbeiceshi.com`；www 保留为跳转入口 |
| 网站根目录 | `/www/wwwroot/fenbeiceshi`，与 `/www/wwwroot/pingmuce` 分离 |
| 版本与切换 | 本站目录内 `releases/`、`current`、`shared/_next/static/`，不得指向屏幕测目录 |
| Nginx 配置 | 本站独立文件 `fenbeiceshi.conf`，只变更本站 server 块 |
| 日志/缓存区 | 本站独立日志名称和 `fenbeiceshi_ssl` 等共享内存区名称 |
| 证书 | 覆盖本站实际启用的主机名；独立路径和续期配置，不改屏幕测证书 |
| Cloudflare 凭据 | 单独限权到本站 zone；如保留凭据文件，可采用 `/etc/fenbeiceshi/cloudflare.env`，不得提交或打包 |
| CI 标识 | 拟用 `fenbeiceshi-production` 并发组；同一 job 直接 SSH 发布，不创建 GitHub Artifacts；GitHub secret/variable 按项目配置 |
| 回滚/清理 | 只处理本站版本与资源；不得删除另一产品文件或清除另一 zone 缓存 |

同机可以沿用基础 Nginx 与 SSH 能力，但域名所有权、凭据可用性和现有配置兼容性仍需在部署任务中核实。本次不复制密钥、不执行 SSH、不改 DNS 或生产配置。

## 6. 必须适配的参考项目专属内容

参考脚本并非可直接调用的通用模板：

1. `deploy/setup-server.sh` 限定 `pingmuce.com` 和以 `/pingmuce` 结尾的部署目录；Nginx 配置文件名、证书域名和临时目录也有专属命名。
2. `deploy/remote-release.sh` 同样校验域名与路径；应建立本站白名单与路径防护，不能简单删除安全校验。
3. 工作流含项目并发组、产物名、域名、默认发布目录和凭据路径；集成测试也有专属 hosts 条目，需逐项适配。
4. `src/lib/metadata.ts` 等公开内容中的站点 URL、品牌、语言假设与路径注册需要替换为本项目的数据。
5. **Nginx 模板禁用了麦克风**：`deploy/nginx/pingmuce.conf.template` 的 server 和静态资源 location 中均包含 `microphone=()`，不能照搬到分贝测试。

分贝测试主文档的拟定响应头：

```http
Permissions-Policy: camera=(), microphone=(self), geolocation=()
```

这只是允许同源页面请求麦克风，不会代替用户授权。被策略阻断时，支持该策略的浏览器会让 `getUserMedia()` 失败；还需要验证 HTTPS、安全上下文和浏览器设置。[权限策略说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy/microphone) [getUserMedia 说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

检查响应头时覆盖主文档、带尾斜杠路径、英文路由及所有设置了 `add_header` 的 location；参考模板特意重复部分头以应对继承行为。Cloudflare 若有响应头规则也必须一起核对。不通过全站开放所有来源解决问题；第三方嵌入测量暂不进入首版范围。

## 7. Cloudflare、TLS、缓存与状态码

- 建议按本站配置 Full (strict)，确认源站 443 与匹配本站域名的有效证书；先验证源站条件，避免证书不匹配引发访问错误。[官方要求](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/)
- 公开链接全部使用 HTTPS 与规范域名；www/HTTP 永久跳转保留原路径和必要查询参数。尾斜杠策略也保持一致。
- `_next/static` 哈希资源采用长缓存；保留旧版本资源以支持已打开的页面。HTML 采用可及时更新的缓存策略，避免旧正文和新脚本混用。
- 不假定 Cloudflare 默认缓存 HTML；先检查实际 Cache Rules、Worker 与响应头，再决定是否设置 HTML 边缘缓存及发布失效方式。[默认缓存行为](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)
- 若使用版本标记进行健康检查，标记响应 `no-store`，验证本次部署版本而非旧缓存。
- 保留 `try_files ... =404` 和真实 404；不能用所有路径回退首页的 SPA 规则。
- 核对安全、Bot/WAF 与挑战规则是否影响正常用户及目标搜索引擎抓取；按实际请求记录处理，不盲目关闭整站防护。

## 8. 本地验证入口

已接入 ESLint flat config、Prettier 与 TypeScript strict；脚本职责与参考项目保持一致。新增或调整检查配置前读取 `react-next-lint-format` 技能。

| 实际命令 | 检查职责 |
| --- | --- |
| `npm run format:check` | 文件格式，仅检查 |
| `npm run lint` | 静态规则与 Hooks 等问题；是否阻断警告由配置明确 |
| `npm run typecheck` | strict 类型检查 |
| `npm run test` | 信号算法、校准有效性、统计口径、记录迁移、计算边界等必要测试 |
| `npm run test:content` | 路由唯一性、来源字段、语言关系、关联 ID 与已发布内容一致性 |
| `npm run build` | 静态导出和内容路由完整性 |
| `npm run test:export` | 产物 HTML、canonical、语言关系、正文、站内链接、sitemap 与 noindex |
| `npm run check` | 运行已接入的完整检查，与 CI 相同 |

实际运行结果见验证记录。`npm run preview` 在本机预览 `out/`，返回真实 404 并设置同源麦克风策略；不能代替生产响应头验证。部署脚本接入后，再按实际实现添加 pack、发布及集成测试入口，不创建空壳脚本冒充验证。

功能实现后的手工验收至少覆盖：

- 未授权、等待授权、拒绝、无设备、设备占用、运行中断、结束与清除记录；停止后释放音轨。
- 通用估算与可选参考校准的统一投影，模型版本、旧记录兼容及设备/处理设置变化后的有效性；数值一致性测试不能代替真实声学精度验证。
- 桌面 Chrome、手机 Safari/Chrome 的实际浏览器与设备组合；记录具体版本和范围，不能用模拟视口替代音频实测。
- 中文与英文、键盘与触控、减少动画设置；首屏操作与读数层级符合 V2 设计。
- 构建 HTML 中的正文、canonical、alternate、来源与链接；记录页 noindex、缺失路径 404。

部署任务中的检查顺序为：本地/CI 通过 → 校验本站产物 → 源站与配置预检 → 发布到本站版本目录 → 原子切换 → 验证版本、状态码、TLS、缓存及麦克风 → 失败则回滚本站版本。新增或变更 Nginx 时先做配置检查，再按实际授权执行 reload。
